# Meerdere accounts op één Tick: bouwplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eén Tick met meerdere accounts. Iedereen ziet alleen zijn eigen taken, plekken, sleutels, telefoons, meldingen en instellingen. De beheerder nodigt mensen uit met een link en maakt resetlinks, en een bestaande installatie wordt zonder verlies één beheerder.

**Architecture:** Nieuwe tabellen `users`, `user_settings` en `account_links`, plus een kolom `user_id` op elke tabel met persoonlijke gegevens. Bestaande rijen krijgen via een vaste beheerder-id als standaardwaarde de beheerder. De Worker leidt uit elke request een `userId` af (sessiecookie `exp.userId.version.hmac`, sleutel, oude secrets → beheerder) en elke query filtert daarop. Tijdrekenwerk krijgt de zone van de gebruiker mee en leunt niet op een globale waarde over een `await` heen. De PWA en de Android-app houden hun lokale gegevens per gebruiker en wissen ze bij een wissel.

**Tech Stack:** Cloudflare Worker (Hono, D1, vitest met `@cloudflare/vitest-plugin`), PWA zonder build-stap, Android (Java 17, JUnit).

**Spec:** `docs/superpowers/specs/2026-10-17-accounts-design.md`

## Global Constraints

- Werk op branch `accounts` (staat op `android-twa`). Alleen lokaal committen; niet pushen, deployen of mergen zonder akkoord van Dio.
- Regels uit `CLAUDE.md`:
  - een nieuwe instelling komt in `wrangler.example.jsonc` (veilige standaard en comment), in `wrangler.jsonc` en in het `Env`-type in `src/index.ts` (dit plan voegt geen config toe);
  - alle zichtbare tekst via `public/i18n.js`, met een `en`- en een `nl`-waarde (dezelfde sleutels, `test/i18n.test.ts`);
  - serverfouten via `HttpError(status, key, vars)`, nooit een zin.
- Migraties: alleen nieuwe bestanden. Dit plan voegt `0008_users.sql`, `0009_user_id.sql` en `0010_settings_cleanup.sql` toe en wijzigt geen bestaande migratie.
- PWA: geen build-stap, geen inline scripts of stijlen (CSP). Een nieuwe app-module komt in `SHELL` in `public/sw.js` en `CACHE` gaat omhoog (nu `tick-shell-v9`). Dit plan voegt geen app-module toe. `/accountlink.js` is een bestand van de inlogpagina's (in `loginAssets`, net als `/login.js`) en komt dus niet in `SHELL`.
- Tijd: opslaan in UTC. Een tijd zonder zone en ritmes gebruiken de zone van de huidige gebruiker (zie Task 5).
- Comments en commitberichten in het Nederlands. Elk commitbericht eindigt met `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Vaste waarden uit de spec:
  - uitnodigingslink `/invite/<code>`: eenmalig, **7 dagen** geldig;
  - resetlink `/reset/<code>`: eenmalig, **1 uur** geldig;
  - van beide links wordt alleen de hash bewaard (zoals bij koppelcodes), en verbruiken gebeurt in één statement;
  - wachtwoord minimaal **8 tekens** (`MIN_PASSWORD = 8`);
  - sessiecookie `exp.userId.version.hmac`, met `version` = `users.session_version`. Oude cookies (zonder gebruiker) zijn ongeldig;
  - de migratie maakt één `admin`: naam `"Tick"`, `email` NULL, `password_hash` uit `settings` (of NULL), `session_version` uit `settings`;
  - inloggen met e-mailadres en wachtwoord, met één neutrale fout voor een onbekend adres of een fout wachtwoord. Een leeg e-mailadres logt in als de beheerder zolang die geen e-mailadres heeft;
  - `LOGIN_PASSWORD` geldt alleen voor de beheerder, en alleen zolang die geen `password_hash` heeft;
  - `API_TOKEN`, `INBOX_TOKEN` en `DEV_AUTH_BYPASS` horen bij de beheerder;
  - `FALLBACK_WEBHOOK` uit de config geldt alleen voor de beheerder. `TIMEZONE` en de standaard herinneringstijd gelden voor iedereen;
  - TickTick-ids zijn `tt<taskId>` voor de beheerder en `tt<eerste 8 tekens van userId>-<taskId>` voor anderen;
  - een id van een ander account gedraagt zich als een id die niet bestaat;
  - Android wist bij een wissel `cache`, `pending`, `pendingRemind`, `locFired`, `locSynced` en `geoSig`.
- Eigen vaste keuzes:
  - `ADMIN_ID = '00000000-0000-4000-8000-000000000001'` (`src/users.ts`) is de id van de beheerder uit de migratie, ook op een verse installatie;
  - rate limit op de links via `LOGIN_LIMITER` met sleutel `'link:' + ip`.
- Tests delen één D1. Een test die de beheerder wijzigt (`email`, `password_hash`, `session_version`), zet die in `afterEach` terug. Extra gebruikers maak je met `createUser()` (Task 2), met een uniek e-mailadres.
- Verifiëren:
  - `npm run typecheck` en `npm test` zijn groen na elke task;
  - Android, in `android/`: `JAVA_HOME="C:\Program Files\Microsoft\jdk-21.0.12.101-hotspot" ./gradlew testDebugUnitTest assembleDebug` geeft BUILD SUCCESSFUL;
  - UI: `npm run dev` en controleren in de browser (preview_start).

## Review Focus

1. **Client-id van een ander account:** B stuurt `POST /api/tasks` met een `id` die bij A hoort (een geraden id of een verdwaalde outbox). Verwacht: 409 `err.id_taken`, geen 500, en A's taak blijft onveranderd en onzichtbaar (test in Task 3).
2. **Dezelfde lijstnaam bij twee accounts:** A en B hebben allebei een lijst "Werk". B's hernoemen of verwijderen (`tasks: 'delete'`) raakt alleen B's taken (test in Task 3).
3. **Twee mensen koppelen tegelijk:** B vraagt een koppelcode aan net nadat A's code is ingewisseld. A's `GET /api/pair/:id` moet nog `{used: true}` geven, anders blijft A's PWA peilen en meldt hij "koppelen mislukt" (test in Task 6).
4. **Mislukte aanmelding verbrandt de link niet:** een uitnodiging met een bestaand e-mailadres of een te kort wachtwoord geeft een fout. Daarna werkt dezelfde link nog wel (test in Task 9).
5. **Backup met een subtaak onder A's taak:** B zet een bestand terug waarin een subtaak als `parent_id` een id van A heeft. Verwacht: de subtaak wordt bij B een gewone taak (`parent_id` null), en A's taak krijgt geen kind (test in Task 7).

`migrations/0008_users.sql` (exact):
```sql
-- Meerdere accounts. De bestaande installatie (en een verse) wordt één beheerder met een vaste id.
CREATE TABLE users (
  id              TEXT PRIMARY KEY,
  name            TEXT NOT NULL,
  email           TEXT UNIQUE COLLATE NOCASE,
  password_hash   TEXT,
  role            TEXT NOT NULL CHECK (role IN ('admin','member')),
  session_version INTEGER NOT NULL DEFAULT 1,
  created_at      TEXT NOT NULL,
  last_seen       TEXT
);
INSERT INTO users (id, name, email, password_hash, role, session_version, created_at)
SELECT '00000000-0000-4000-8000-000000000001', 'Tick', NULL,
  NULLIF((SELECT value FROM settings WHERE key = 'password_hash'), ''), 'admin',
  COALESCE((SELECT CAST(value AS INTEGER) FROM settings WHERE key = 'session_version'), 1),
  strftime('%Y-%m-%dT%H:%M:%fZ', 'now');

-- Instellingen per persoon; settings houdt alleen wat voor de hele installatie geldt.
CREATE TABLE user_settings (
  user_id TEXT NOT NULL REFERENCES users(id),
  key     TEXT NOT NULL,
  value   TEXT NOT NULL,
  PRIMARY KEY (user_id, key)
);
INSERT INTO user_settings (user_id, key, value)
SELECT '00000000-0000-4000-8000-000000000001', key, value FROM settings
WHERE key IN ('timezone', 'reminder_time', 'week_start', 'fallback_webhook');

-- Uitnodigings- en resetlinks; alleen de SHA-256 van de code staat hier.
CREATE TABLE account_links (
  id         TEXT PRIMARY KEY,
  hash       TEXT NOT NULL UNIQUE,
  kind       TEXT NOT NULL CHECK (kind IN ('invite','reset')),
  user_id    TEXT REFERENCES users(id),
  created_by TEXT NOT NULL REFERENCES users(id),
  expires_at TEXT NOT NULL,
  used_at    TEXT
);
```

`migrations/0009_user_id.sql` (exact):
```sql
-- Elke persoonlijke rij hoort bij een account; bestaande rijen bij de beheerder. SQLite staat bij ADD COLUMN geen
-- REFERENCES met een standaardwaarde toe; een account verwijderen ruimt de Worker daarom zelf op.
ALTER TABLE tasks ADD COLUMN user_id TEXT NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001';
ALTER TABLE push_subscriptions ADD COLUMN user_id TEXT NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001';
ALTER TABLE api_keys ADD COLUMN user_id TEXT NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001';
ALTER TABLE pair_codes ADD COLUMN user_id TEXT NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001';
CREATE INDEX idx_tasks_user ON tasks (user_id, done, position);
CREATE INDEX idx_push_user ON push_subscriptions (user_id);
CREATE INDEX idx_keys_user ON api_keys (user_id);

-- Plekken: de naam is uniek per account. Een constraint aanpassen kan niet in SQLite, dus opnieuw opbouwen.
CREATE TABLE places_new (
  id         TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL DEFAULT '00000000-0000-4000-8000-000000000001' REFERENCES users(id),
  name       TEXT NOT NULL COLLATE NOCASE,
  lat        REAL NOT NULL,
  lng        REAL NOT NULL,
  radius     INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (user_id, name)
);
INSERT INTO places_new (id, user_id, name, lat, lng, radius, created_at, updated_at)
SELECT id, '00000000-0000-4000-8000-000000000001', name, lat, lng, radius, created_at, updated_at FROM places;
DROP TABLE places;
ALTER TABLE places_new RENAME TO places;
```
